


Vizito Patient Application – Functional Requirements Document

Module 1: Authentication & Onboarding




1. Overview

The Authentication and Onboarding module allows users to securely access the Vizito Patient Application and create a patient account with minimal information. The onboarding process is designed to be simple, enabling users to complete registration quickly while collecting only the essential information required to use the application.




2. Objectives

Allow new users to register with minimal information.

Provide multiple secure login methods.

Enable quick account creation.

Support OTP-based and password-based authentication.

Ensure a smooth onboarding experience before accessing the application.




3. Authentication Methods

The application shall support the following login methods:

Mobile Number + OTP

Email Address + OTP

Mobile Number + Password

Email Address + Password

The user may choose any available authentication method from the login screen.




4. Login Screen

Purpose

Allow existing users to securely access the application.




Screen Description

The Login screen is the first screen displayed when the application is opened by a user who is not authenticated.

Users can select their preferred login method and continue with authentication.




UI Components

Vizito Logo

Welcome Message

Authentication Method Selector

Mobile Number Input

Email Address Input

Password Input

OTP Input (displayed only when OTP authentication is selected)

Send OTP Button

Verify OTP Button

Login Button

Forgot Password

Create New Account

Only the fields relevant to the selected authentication method shall be displayed.




User Actions

The user can:

Select a login method.

Enter a mobile number.

Enter an email address.

Enter a password.

Request an OTP.

Verify the received OTP.

Log in to the application.

Navigate to account registration.

Navigate to the Forgot Password screen.




Business Rules

Only one authentication method shall be active at a time.

OTP authentication requires successful OTP verification before login.

Password authentication requires valid credentials.

Successful authentication redirects the user to the application dashboard.

Invalid authentication prevents login.




Validations

Mobile Number

Mandatory for mobile authentication.

Must be a valid mobile number.

Email Address

Mandatory for email authentication.

Must be in a valid email format.

Password

Mandatory for password authentication.

OTP

Mandatory for OTP authentication.

OTP must be successfully verified before login.




Success Scenario

Authentication is successful.

User is redirected to the Home Dashboard.




Failure Scenario

Invalid mobile number.

Invalid email address.

Incorrect password.

Invalid OTP.

Expired OTP.

Authentication failure.

Appropriate validation or error messages shall be displayed, and the user shall remain on the Login screen until authentication succeeds.




Acceptance Criteria

User can log in using Mobile Number + OTP.

User can log in using Email + OTP.

User can log in using Mobile Number + Password.

User can log in using Email + Password.

Only the selected authentication method is displayed.

Successful authentication redirects the user to the Home Dashboard.




5. Forgot Password

Purpose

Allow users to securely reset their account password.




Screen Description

Users can recover access to their account by verifying their registered mobile number or registered email address using OTP before creating a new password.




UI Components

Mobile Number / Email Input

Send OTP Button

OTP Input

Verify OTP Button

New Password

Confirm Password

Reset Password Button




User Actions

Enter registered mobile number or email.

Request OTP.

Verify OTP.

Create a new password.

Confirm the new password.

Submit the password reset request.




Business Rules

Password reset is allowed only after successful OTP verification.

The new password becomes the active password after a successful reset.




Validations

Registered mobile number or email is required.

OTP verification is mandatory.

New Password is required.

Confirm Password must match the New Password.




Success Scenario

The password is successfully updated, and the user is redirected to the Login screen.




Failure Scenario

Invalid or expired OTP.

Password confirmation mismatch.

Password reset failure.




Acceptance Criteria

User can reset the password using Mobile Number + OTP.

User can reset the password using Email + OTP.

User is redirected to the Login screen after a successful password reset.




6. New User Registration

Purpose

Allow new users to create a Vizito patient account using only the minimum required information.




Registration Flow

Verify Mobile Number or Email using OTP.

Enter Personal Information.

Enter Address.

Create Password.

Registration Completed.




7. Personal Information

Purpose

Collect the minimum personal information required to create a patient account.




UI Components

Full Name

Mobile Number

Email Address (optional if registering using a mobile number)

Password

Confirm Password

Continue Button




User Actions

Enter personal information.

Create a password.

Continue to the Address section.




Business Rules

Mobile number must be verified through OTP before registration is completed.

If registration is initiated using an email address, the email must be verified through OTP before registration is completed.

Password setup is mandatory for every account.




Validations

Full Name

Mandatory.

Mobile Number

Mandatory.

Must be verified if used for registration.

Email Address

Mandatory only when email is selected as the registration method.

Must be verified if used for registration.

Password

Mandatory.

Confirm Password

Must match the Password.




8. Address Information

Purpose

Capture the patient's primary address.




Screen Description

The application attempts to automatically capture the user's current address. Users may also manually enter or modify the address before saving.




UI Components

Auto Capture Address

Manual Address Entry

Save Address Button

Complete Registration Button




User Actions

Capture the current address automatically.

Manually enter the address.

Edit the captured address if required.

Save the address.

Complete registration.




Business Rules

Users may either use the automatically captured address or manually enter the address.

The address can be modified before completing registration.




Validations

An address must be available before registration is completed.




Success Scenario

The patient account is successfully created, and the user is redirected to the Home Dashboard.




Failure Scenario

Registration cannot be completed if mandatory information is missing.

Registration cannot be completed if OTP verification has not been successfully completed.




Acceptance Criteria

User can register using Mobile Number + OTP.

User can register using Email + OTP.

Registration requires only:

Personal Information

Address

Password Setup

Address supports both automatic capture and manual entry.

Successful registration redirects the user to the Home Dashboard.

Module 2: Home Dashboard




1. Overview

The Home Dashboard is the primary landing screen of the Vizito Patient Application after successful authentication. It serves as the central navigation point, allowing patients to quickly access all available healthcare services, view active bookings, manage family members, and continue their healthcare journey from a single screen.

The dashboard is designed to provide quick access to the most frequently used features while maintaining a clean and consistent user experience.




2. Objectives

Provide quick access to all healthcare services.

Enable patients to search across all available services.

Display ongoing activities and bookings.

Provide easy access to family members.

Allow users to continue unfinished or upcoming bookings.

Serve as the primary navigation hub of the application.




3. Home Dashboard

Purpose

Provide patients with a centralized view of healthcare services, current activities, and quick navigation throughout the application.




Screen Description

The Home Dashboard is displayed immediately after a successful login.

The screen presents all available healthcare services in a single place and provides shortcuts to frequently used actions without requiring users to navigate through multiple menus.




UI Components

Header

Greeting Message

User Name

Notification Icon




Global Search

A universal search bar allowing users to search for:

Doctors

Hospitals

Clinics

Home Care Services

Ambulance Services

Pharmacy

Diagnostic Labs

Medical Equipment Rentals

Selecting a search result navigates the user to the appropriate listing or provider details screen.




Healthcare Services

The dashboard shall display the available healthcare services:

Doctor Consultation

Hospital & Clinic

Home Care

Ambulance

Pharmacy

Diagnostic Lab

Equipment Rental

Selecting a service opens the corresponding service listing.




Active Bookings

Displays the patient's ongoing bookings across all services.

Each booking card shall display:

Current Status

Selecting a booking opens the Booking Details screen.




Upcoming Bookings

Displays confirmed future bookings.

Each booking card shall display:

Service

Scheduled Time

Selecting a booking opens the Booking Details screen.




Recent Activities

Displays recently completed activities performed by the patient.

Examples include:

Doctor Appointments

Home Care Bookings

Ambulance Bookings

Pharmacy Orders

Lab Bookings

Equipment Rentals

Selecting an activity opens the corresponding Booking Details screen.




Family Members

Displays all registered family members.

The user can:

Select a family member.

Add a new family member.

Selecting a family member filters subsequent bookings and activities for that individual.




Favorites

Displays providers saved by the patient.

Supported provider types include:

Doctors

Hospitals

Clinics

Ambulance Providers

Pharmacies

Diagnostic Labs

Bottom Navigation

The application shall provide persistent navigation to:

Home

Search

Bookings

Profile




User Actions

The user can:

Search for healthcare services.

Select a healthcare service.

View active bookings.

View upcoming bookings.

View recent activities.

Open booking details.

Select a family member.

Add a new family member.

Open favorite providers.

View notifications.

Navigate using the bottom navigation bar.




Business Rules

The Home Dashboard is displayed only after successful authentication.

Active bookings shall display the latest booking status.

Upcoming bookings shall display only confirmed future bookings.

Recent activities shall display completed bookings.

Selecting a family member applies to the user's current session until another member is selected or the user switches back to themselves.

Favorites shall display only providers saved by the logged-in patient.




Success Scenario

Dashboard loads successfully.

Healthcare services are available for selection.

Active bookings and upcoming bookings are displayed correctly.

The patient can navigate to any module from the dashboard.




Failure Scenario

If dashboard information cannot be loaded, the application shall display an appropriate message while keeping the user on the Home Dashboard.

If no active or upcoming bookings exist, the corresponding sections shall display an empty state.

If no favorites have been added, the Favorites section shall display an empty state.




Acceptance Criteria

Dashboard is displayed after successful login.

All supported healthcare services are available from the dashboard.

Universal Search is accessible from the dashboard.

Active bookings display the latest booking status.

Upcoming bookings display confirmed future bookings.

Recent activities display completed services.

Family members are accessible from the dashboard.

Favorite providers are accessible from the dashboard.

Bottom navigation is available throughout the application.

Module 3: Universal Booking Flow




1. Overview

The Universal Booking Flow provides a single and consistent booking experience across all healthcare services available in the Vizito Patient Application.

Instead of creating separate booking flows for each service, the application uses one reusable booking process. The fields and options displayed during the booking process automatically adapt based on the selected service.

This approach ensures a consistent user experience while reducing duplicate screens and simplifying future maintenance.




2. Supported Services

The Universal Booking Flow shall be used for:

Doctor Consultation

Hospital & Clinic

Home Care Services

Scheduled Ambulance

Pharmacy Orders

Diagnostic Lab

Equipment Rental




3. Booking Flow

Every booking shall follow the same sequence.

Step 1 – Select Service

The user selects one of the available healthcare services.

Examples:

Doctor Consultation

Hospital & Clinic

Home Care

Ambulance

Pharmacy

Diagnostic Lab

Equipment Rental

The selected service determines the fields displayed in subsequent steps.




Step 2 – Select Provider

The application displays the available providers for the selected service.

Each provider card may display information relevant to the selected service.

Examples include:

Provider Name

Rating

Availability

Location

Consultation Fee

Rental Price

Service Charges

Selecting a provider opens the booking process.




Step 3 – Select Patient

The patient selects who the booking is for.

Available options:

Myself

Registered Family Member

If required, the user may add a new family member before continuing.




Step 4 – Booking Details

The application displays only the fields applicable to the selected service.

Examples include:

Doctor Consultation

Consultation Type

Appointment Date

Time Slot

Hospital & Clinic

Department

Appointment Date

Time Slot

Home Care

Service Type

Visit Date

Visit Time

Service Address

Scheduled Ambulance

Pickup Address

Destination

Pickup Date

Pickup Time

Pharmacy

Medicine Selection

Prescription Upload (if required)

Diagnostic Lab

Test Selection

Home Collection or Lab Visit

Appointment Date

Time Slot

Equipment Rental

Equipment Selection

Rental Duration

Delivery Address

Only the fields applicable to the selected service shall be displayed.




Step 5 – Review Booking

The application displays a summary of the booking before confirmation.

The summary includes only information relevant to the selected service.

Typical information may include:

Service

Provider

Patient

Date

Time

Address (if applicable)

Charges

The user may return to previous steps to make changes before proceeding.




Step 6 – Payment

The user completes payment using the available payment methods.

After successful payment, the booking is confirmed.




Step 7 – Booking Confirmation

The application displays the booking confirmation.

The confirmation includes:

Booking Reference

Service

Provider

Available actions may include:

Cancel Booking (subject to provider policy)

Return to Home




4. User Actions

The user can:

Select a healthcare service.

Select a provider.

Select a patient.

Enter booking details.

Review the booking.

Complete payment.

Confirm the booking.

View the booking.

Track the booking where applicable.

Cancel the booking where permitted.

Rebook an existing booking.




5. Business Rules

A single booking flow shall be used for all supported healthcare services.

Only fields relevant to the selected service shall be displayed.

Booking cannot proceed until all mandatory information has been completed.

Booking is confirmed only after successful payment.

Tracking shall be available only for supported services.

Cancellation and rebooking options shall be displayed according to the booking status.




6. Success Scenario

The booking is successfully completed.

Payment is successful.

Booking confirmation is displayed.

The booking appears under the patient's bookings.




7. Failure Scenario

Booking may fail due to:

Incomplete booking information.

Provider unavailability.

Slot no longer available.

Payment failure.

Booking could not be completed.

The application shall notify the user and allow them to retry where applicable.




8. Acceptance Criteria

A single booking flow is used across all supported services.

The booking flow dynamically displays fields based on the selected service.

Users can complete a booking using the same navigation sequence regardless of service type.

Bookings are confirmed only after successful payment.

Confirmed bookings are available in the patient's booking history.

Module 8: Universal Queue Management




1. Overview

The Universal Queue Management module provides patients with real-time visibility into their position in a service queue after a booking has been confirmed.

A single queue management screen shall be used across all supported healthcare services where queue-based appointments are applicable. The layout remains consistent while the displayed information changes according to the selected service.

This module is intended to improve patient visibility into waiting times and queue progress.




2. Objectives

Display the patient's current queue information.

Provide estimated waiting information.

Reduce uncertainty before appointments.

Maintain a consistent queue experience across supported services.




3. Applicable Services

Queue Management shall be available only for:

Doctor Consultation

Hospital & Clinic

Diagnostic Lab (where queue-based appointments are used)

Queue Management is not applicable to:

Home Care Services

Scheduled Ambulance

Pharmacy Orders

Equipment Rental




4. Queue Screen

Purpose

Allow patients to monitor their current position in the service queue before their appointment or service begins.




Screen Description

The Queue Management screen displays the patient's current queue information and updates as the queue progresses.

The screen is accessible from the Booking Details screen whenever queue management is supported by the selected provider.




UI Components

Queue Summary

Displays:

Booking Reference

Service Type

Provider Name

Appointment Date

Appointment Time




Queue Information

Displays:

Queue Number

Current Queue Number

Number of Patients Ahead

Estimated Waiting Time

Queue Status




Queue Status

The queue status may include:

Waiting

Current

Completed

Cancelled

Only one status shall be active at a time.




5. User Actions

The user can:

View queue information.

Monitor queue progress.

Return to Booking Details.




6. Business Rules

Queue information shall only be displayed for providers that support queue management.

Queue information shall reflect the latest available status.

Queue updates shall be reflected automatically as they are received from the provider.

Once the appointment has been completed, the queue information shall no longer be active.
